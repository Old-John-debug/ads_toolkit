# 简化布局计划

如果不想手算坐标和连线，可以写“布局计划”，让工具生成完整的 v1 文本。适合单主链网络：源 → 串联器件 → 输出节点，配合对地支路、探针和控制器。

生成结果仍然是完整的方案 A 文本，不会绕过几何审计、连接核对或参考网表比较。

## 1. 文件格式

与 v1 相比：

- `[器件]` 只有 4 列：`名称 | 库 | 单元 | 参数`，不写坐标和角度。
- 不需要 `[连线]`。
- 新增 `[布局]`，写器件角色。
- GROUND 器件自动放到地总线上，不需要列在布局分类中。

骨架：`templates/layout_plan_skeleton.txt`  
合成示例：`examples/specs/demo_layout.plan.txt`

```text
版本 = 1
[工程] ...
[变量] ...
[器件] 名称 | 库 | 单元 | 参数
[网络] 网络 = 器件.引脚, ...
[布局]
主链 = P1, I_Probe1, L2, D1
对地 = L1, C1, C2, R1
探针 = V_IN, V_OUT
控制器 = HB1, Sweep1, VAR1
[选项] ...
```

### 主链

从左到右排列。第一个必须是源，且只连接一个信号网络；后续每个器件必须连接前一个节点和下一个节点。多脚器件（例如六脚二极管阵列）的额外同网引脚会自动绕到符号外侧并接，避免压着符号边缘、看不清连接。

### 对地

每个器件必须恰好连接一个主链信号网络和地网络。工具选择向下的旋转，把信号脚放在主链上、地脚接到总线。

### 探针

只支持单脚探针。工具把它放在对应节点下方，并补一小段竖直连线。

### 控制器

HB、ParamSweep、VAR 等无引脚控制器放在下方独立行。它们仍必须在 `[器件]` 和 `[网络]` 之外被声明，并列入控制器。

### 其他要求

- 必须至少有一个 `GROUND` 器件。
- 所有非 GROUND 器件必须且只能出现在一个布局分类中。
- 所有信号网络都必须在主链上；不支持多条并行主链或任意网络自动布线。
- 标准器件从 `templates/device_pin_table.json` 取 R0 偏移；项目专属/厂商器件用 `--pin-table` 提供项目引脚表，不写进工具包核心。
- 坐标会吸附到 0.25 用户单位网格，避免 ADS 放置时产生偏移。
- 移动 ADS 中的器件不会带动已有连线；改布局应改 plan/spec 后重新生成，不要靠 GUI 拖动。

## 2. 生成与检查

```bat
"<ADS>\tools\python\python.exe" -B -m adstk layout examples/specs/demo_layout.plan.txt my_demo.txt
```

输出是完整的 v1 文本。接着仍然要运行：

```bat
"<ADS>\tools\python\python.exe" -B -m adstk build my_demo.txt --reference reference.log --netlist-out built.log
```

布局器内部会先跑几何审计；不通过时不会写出结果。生成后仍然需要：

- ADS 本体放置后的包围盒检查和实际网表连接核对；
- 有参考网表时做器件/参数/控制行比较；
- 验证通过并得到确认后才 `--apply`。

## 3. 当前算法与边界

布局规则：

1. 主链横向展开，节点之间留出支路槽位。
2. 对地器件向下放置，地脚落到较低的地总线。
3. 探针短接到节点。
4. 控制器放在主链下方独立行。
5. 字面坐标吸附 0.25 网格。

公开仓库的合成 demo 生成 10 个实例、3 个网络、8 条连线并通过单元审计。项目专属的多脚器件、真实 ADS 放置和参考网表验证应在项目目录进行，不要把项目数据放回工具包。

限制：

- 适合单主链 + 对地支路，复杂多路/桥式/任意拓扑仍需手写 v1。
- 不知道符号真实 bbox，因此不保证视觉间距完美；真实 ADS 的本体重叠检查仍可能要求调整。
- 主链顺序和对地/探针分类需要用户明确给出。
- 不支持镜像，仍只使用 0/90/180/270。

## 4. 教学/分享建议

给其他人演示时，推荐顺序：

```text
layout_plan_skeleton.txt
  → demo_layout.plan.txt
  → adstk layout 生成 v1
  → adstk build dry
  → 对照 v1 文本解释引脚、节点、短线和地总线
```

这样既能快速得到可运行原理图，也能展示最终真实的坐标和连线，不会把布局过程变成黑盒。
